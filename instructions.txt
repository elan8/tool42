# Tool42 Usage Instructions for AI Agents

## Overview

Tool42 is an MCP (Model Context Protocol) server that provides structured JSON responses for Rust codebases. Always use tool42 MCP tools instead of direct cargo commands and for Rust software engineering tasks.

## Available Tools

- `tool42_cargo` - Execute Cargo commands with pagination support (use instead of direct `cargo` commands)
- `tool42_clippy` - Execute cargo clippy with pagination support. Requires clippy to be installed (`rustup component add clippy`)
- `tool42_read` - Read files or specific sections with line number limits (max 500 lines)
- `tool42_describe` - Parse Rust source file and extract comprehensive structural information (structs, enums, functions, impl blocks, traits, modules, etc.) with line numbers, visibility, attributes, doc comments, and signatures in JSON format
- `tool42_search` - Search for text patterns across the codebase
- `tool42_deps` - Extract dependency information from Cargo.toml
- `tool42_tests` - List all tests in the project
- `tool42_project` - Get overview of project structure
- `tool42_list` - List directory contents with metadata
- `tool42_docs` - Extract doc comments from Rust code

## Critical Rules

1. **Always use tool42 MCP tools** instead of direct cargo commands for Rust-related tasks
2. **Working Directory Parameter**: The `working_directory` input parameter for ALL tool42 MCP tools **MUST be an absolute path**
3. **Structured Responses**: All tools return structured JSON directly - no temp files or stdout parsing needed

## When to Use Each Tool

- **tool42_cargo**: For any Cargo command (build, test, check, etc.). Supports pagination for large outputs - use `from`/`to` parameters to request specific line ranges
- **tool42_clippy**: For clippy linting. Supports pagination for large outputs - use `from`/`to` parameters to request specific line ranges. Returns error if clippy is not installed
- **tool42_read**: When you need to read Rust source files or specific sections
- **tool42_describe**: To understand the complete structure of a Rust file including all items (structs with fields, enums with variants, functions with signatures, impl blocks with nested methods, traits with associated items, modules with nested items, type aliases, constants, static items, macros, etc.) along with their line numbers, visibility, attributes, and doc comments
- **tool42_search**: To find code patterns, function names, or text across the codebase
- **tool42_deps**: To understand project dependencies
- **tool42_tests**: To discover and list all tests in the project
- **tool42_project**: To get a high-level overview of the project structure
- **tool42_list**: To explore directory contents
- **tool42_docs**: To extract documentation comments from Rust code

## Best Practices

- Always provide absolute paths for `working_directory` parameter
- Use structured JSON responses directly - don't parse stdout or create temp files
- Prefer tool42 tools over direct shell commands for Rust tasks
- Use `tool42_describe` to quickly understand file structure before reading
- Use `tool42_search` for codebase-wide searches instead of grep
- For large cargo/clippy outputs, use pagination: first call returns first 500 lines, then use `from`/`to` to request specific ranges
